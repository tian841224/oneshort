# API 概覽

本頁從產品功能說明前後端如何溝通。這是架構導覽，未提供完整的第三方串接規格。

## HTTP 與 WebSocket

- **HTTP API**：主要使用 `/api/v2`，負責查詢資料、登入、提交申請與管理操作。
- **WebSocket**：透過 `/ws` 接收隊伍、聊天、公會及通知更新。
- **使用範圍**：依功能區分公開瀏覽、訪客及登入操作；隊伍和公會內容另依目前資格與權限判斷。

能開啟頁面不代表能執行頁面上的所有操作，後端會在請求及即時訂閱時檢查可用範圍。

## 功能分類

| 範圍 | 提供的能力 |
| --- | --- |
| 帳號與角色 | 登入、目前帳號、角色管理、PIN 與 Discord 連結 |
| 隊伍 | 搜尋、建立、詳情、職缺、加入申請、審核與成員管理 |
| 訪客與快速隊伍 | 訪客資料、快速建團、進房、加入與離隊 |
| 個人紀錄 | 我的申請、參與歷史與通知 |
| 公會 | 成員、公告、聊天、隊伍、行事曆、配對偏好與草案 |
| 攻略 | 攻略內容、小工具設定與共享狀態 |
| 平台內容 | 公開公告、活動摘要及問題回報 |

## 幾個代表性查詢

| 查詢 | 用途 |
| --- | --- |
| `GET /api/v2/parties` | 找隊伍頁的隊伍列表 |
| `GET /api/v2/parties/:id` | 隊伍詳情與目前可用操作 |
| `GET /api/v2/applications/me` | 登入玩家送出的申請 |
| `GET /api/v2/actors/me/party-history` | 登入玩家最近 30 天的參與紀錄 |
| `GET /api/v2/guilds` | 公會目錄 |
| `GET /api/v2/notifications` | 個人通知 |

以上只列產品中使用的例子；實際回應與可見資料會依身分及權限不同。

## 操作結果如何反映在畫面

提交操作後，前端先根據 HTTP 結果顯示成功、待審或錯誤，再搭配即時事件更新相關列表與詳情。聊天透過 HTTP 讀取歷史及傳送，WebSocket 提供即時更新。

當名額、角色資格或配對草案已經改變，後端會要求重新確認資料。前端依結果更新，不把送出請求當作操作已完成。
